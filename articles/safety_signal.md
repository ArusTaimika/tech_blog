## 📌 概要

### ⚠️ 課題

プログラムの実行中に `Ctrl+C` を押すと，通常は処理が中断される．しかし，プログラムによっては，モータの停止やソケットの切断など，**アプリケーション固有の終了処理が実行されない**可能性がある．
特にロボットの制御では，プログラムが終了してもモータが動き続けるといった危険な状態につながるおそれがある．

### 💡 結論

Pythonの `signal` モジュールやC++の `std::signal()` を利用すると，`Ctrl+C` による割り込みを検知し，終了処理を実行する流れを明示的に設計できる．
重要なのは，`Ctrl+C` を単に無効化したり，終了を遅らせたりすることではない．**割り込みを検知した後に停止フラグを設定し，通常の処理の中で必要な終了処理を実行することである．**

## 🎯 背景・目的

### 通常の `Ctrl+C` では何が起こるのか？

`Ctrl+C` を押すと，通常は `SIGINT` というシグナルが送られる．シグナルとは，OSからプロセスに対してイベントを通知する仕組みである．
通常の `Ctrl+C` でも，言語やプログラムの実装によっては，例外処理やデストラクタなどによって終了処理が実行される．そのため，`Ctrl+C` を押すと必ずクリーンアップが省略されるわけではない．
一方，モータの停止命令や複数スレッドの終了制御など，**プログラム独自の終了処理が必ず適切に実行されるとは限らない**という問題がある．

### シグナルを捕捉すると何が変わるのか？

シグナルを受け取ったときに実行する関数を「シグナルハンドラ」と呼ぶ．これを登録することで，割り込みを検知した際の動作を指定できる．
通常の終了動作に任せるのではなく，停止フラグを設定して処理ループを終了し，その後にモータ停止やリソース解放などを実行する構成にできる．

| 比較項目 | 通常の `Ctrl+C` | シグナルを捕捉する場合 |
|---|---|---|
| 割り込み | 標準の動作に従う | ハンドラで検知できる |
| 処理ループ | 割り込み時の動作に依存する | 停止フラグで終了を制御できる |
| 独自の終了処理 | 実装次第 | 実行する流れを明示できる |
| 複数スレッド | 各処理の終了制御が必要 | 停止通知を各スレッドに伝えられる |

## 🛠️ 手順・苦戦ポイント

### ① Pythonで実装する

Pythonでは，`signal` モジュールを使ってシグナルハンドラを登録できる．
以下は，`Ctrl+C` を検知したら停止フラグを設定し，ループを抜けてから終了処理を実行する例である．

```python
import signal
import threading
import time

# 停止通知用のイベント
stop_event = threading.Event()

# シグナルハンドラ
def handle_sigint(signum, frame):
    stop_event.set()

# SIGINTを捕捉する
signal.signal(signal.SIGINT, handle_sigint)

def main():
    print("処理を開始します．Ctrl+Cで停止します．")

    try:
        while not stop_event.is_set():
            # 通常の処理
            print("実行中...")
            time.sleep(0.5)

    finally:
        # 通常の処理から戻って終了処理を実行
        print("クリーンアップ処理を実行中...")
        # 例：モータ停止，ファイルやソケットの解放
        print("終了しました．")

if __name__ == "__main__":
    main()
```

#### 🔍 ポイント

- `signal.signal()`：シグナルハンドラを登録する．
- `signal.SIGINT`：`Ctrl+C` に対応するシグナルを指定する．
- `threading.Event()`：スレッド間で共有できる停止通知を作成する．
- `stop_event.set()`：停止通知を設定する．
- `stop_event.is_set()`：停止通知が設定されているか確認する．
- `finally`：正常終了や例外発生時などに，終了処理を実行する．

通常の `Ctrl+C` では，Pythonの標準動作によって `KeyboardInterrupt` が発生する場合がある．今回の例では，`SIGINT` を捕捉して停止イベントを設定することで，ループを抜けて終了処理に進む構成にしている．
なお，`signal` のハンドラはPythonではメインスレッドで実行される．別スレッドの処理を終了させる場合は，`threading.Event()` などで各スレッドに停止を通知し，各スレッド自身が終了できる構造にする必要がある．

### ② C++で実装する

C++では，`std::signal()` を使ってシグナルハンドラを登録できる．
以下は，停止フラグを利用して処理ループを抜け，終了処理を実行する例である．

```cpp
#include <csignal>
#include <iostream>

volatile std::sig_atomic_t running = 1;

// シグナルハンドラ
void handle_sigint(int) {
    running = 0;
}

int main() {
    std::signal(SIGINT, handle_sigint);

    std::cout << "処理を開始します．Ctrl+Cで停止します．"
              << std::endl;

    while (running) {
        // 通常の処理
    }

    // ループを抜けてから終了処理を実行
    std::cout << "クリーンアップ処理を実行中..."
              << std::endl;
    // 例：モータ停止，リソースの解放

    std::cout << "終了しました．" << std::endl;

    return 0;
}
```

#### 🔍 ポイント

- `std::signal()`：シグナルハンドラを登録する．
- `SIGINT`：`Ctrl+C` によるシグナルを指定する．
- `volatile std::sig_atomic_t`：シグナルハンドラと通常の処理との間で，共有するフラグを扱うために利用する．
- `running = 0`：停止フラグを設定する．
- `while (running)`：停止フラグが変更されたらループを終了する．

シグナルハンドラ内では，フラグの設定など，制約に適合した最小限の処理にとどめる．例えば，`std::cout` や `std::cerr` を使った出力，ファイル操作，複雑なクリーンアップ処理などを直接実行することは避ける．
また，この例の `volatile std::sig_atomic_t` はシグナルとの連携を想定したものであり，複数スレッド間の一般的な同期機構ではない．マルチスレッド環境では，シグナルの扱い方やスレッド間の停止通知を別途設計する必要がある．

### ③ 安全に終了するための注意点

シグナルを捕捉することで終了処理の流れを制御できるが，それだけで安全性が保証されるわけではない．
特に，ロボットなどの制御プログラムでは，以下の点に注意する．

- **終了処理を明示する**：モータ停止命令など，必要な処理をループ終了後に実行する．
- **スレッドごとに終了を制御する**：停止通知を受け取った各スレッドが，安全に処理を終了できるようにする．
- **リソースを適切に解放する**：ファイルやソケットなどを，適切なタイミングでクローズする．
- **停止処理の失敗も想定する**：通信断やプログラム異常に備え，ソフトウェア以外の停止機構も検討する．

なお，`SIGKILL` など，ハンドラで捕捉できないシグナルも存在する．また，OSやハードウェアの状態によっては，プログラム側の終了処理を実行できない場合もある．安全性が重要なシステムでは，ソフトウェアの終了処理だけに依存しない設計が必要である．

## 📝 まとめ

今回は，PythonとC++で `Ctrl+C` による割り込みを検知し，終了処理へ移行する方法を整理した．

- 通常の `Ctrl+C` でも，言語や実装によっては終了処理が実行される．
- シグナルを捕捉することで，アプリケーション独自の終了処理へ移行する流れを明示できる．
- ハンドラ内では停止通知などの最小限の処理を行い，クリーンアップは通常の処理の中で実行する．
- ロボット制御では，プログラムの終了とモータの停止を別の問題として考える必要がある．

**重要なのは，プログラムを終了させることだけでなく，終了時にシステムを安全な状態へ移行させることである．**
